# Система замеров

Цель: на каждом шаге (промпт, бюджет, адаптер) знать, **стало ли лучше**, и **почему** агент
проваливает остальные задачи. Работает с результатами официального `swegemma eval`.

> `swegemma` нет в PyPI; он доступен только в окружении конкурса (Kaggle-ноутбук). Ниже команды
> взяты из HARNESS_README.md (раздел 9) и **не проверены** нами на реальной установке.

## 1. Прогон (там, где есть swegemma)

```bash
swegemma eval \
  --tasks data/tasks.jsonl --snapshots-dir data/snapshots \
  --submission-dir submission_v1_noadapter \
  --results-dir results/v1_baseline \
  --sandbox docker --concurrency 2 \
  --max-tool-calls 30 --max-time-minutes 5
# отладка на подмножестве: --task-ids rich_2725 fastapi_11194 ...
# без Docker (если разрешено окружением): --sandbox subprocess
```

Один прогон = один набор настроек. Чтобы сравнивать честно, **всегда одни и те же задачи**
(один и тот же `--task-ids`) и один результат на папку.

## 2. Отчёт

```bash
python evaluation/analyze_results.py report results/v1_baseline
```
Пишет `report.md` и `tasks.csv` в папку прогона. Категории провала:

| категория | значит | что чинить |
|---|---|---|
| `no_patch` | пустой патч / `NO_PATCH` | промпт «всегда сдавай патч», бюджет, зацикливание |
| `patch_apply_failed` | патч не применился | формат правок, мелкие `edit_file` |
| `timeout_or_budget` | вышло время/вызовы | `eval_config.yaml`, меньше разведки |
| `tests_failed` | патч применился, тесты красные | качество решения: аналитик, thinking, SFT |
| `other_error` | не распознано | смотреть `test_outputs/<id>.log` и `traces/` |

Флаги: патч трогает тесты/конфиги (харнесс их сбросит), лишние файлы вроде `repro.py` в патче.
Отчёт печатает доверительный интервал Уилсона: на 13 задачах он шириной ~50 п.п.

## 3. Сравнение двух прогонов

```bash
python evaluation/analyze_results.py compare results/v1_baseline results/v2_prompt
```
Показывает, какие задачи решил только A / только B, и p-value точного теста знаков.
**Правило решения:** принимать изменение только если оно значимо (p < 0.05) или стабильно
повторяется на ≥ 2 независимых прогонах. Агент недетерминирован (T = 0.2), поэтому один прогон
на малой выборке — шум.

## 4. Разумный порядок экспериментов

1. Baseline (`submission_v1_noadapter`) → отчёт → главная категория провала.
2. Бюджет: 3–4 значения `max_time_minutes` / `max_tool_calls` на одном наборе задач.
3. `thinking_budget` (0 / 2048 / 4096) и промпт.
4. Только если остаются `tests_failed` и есть прирост от (1–3) -- SFT/RL, и сравнивать с baseline.

Ограничение: задачи теста взяты из других репозиториев, поэтому не переобучайтесь на метрику
четырёх публичных (fastapi, rich, requests, httpx).

Тесты анализатора: `pytest tests/test_analyze_results.py`.
